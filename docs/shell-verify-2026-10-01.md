### 2. 셸 호환 — 20/20 통과 (`src/server/terminal.shells.test.ts`)

이 머신에 **실제로 있는** 셸 전부로 같은 일을 한다.

| 셸 | 명령 수신·반환 | `cd '<경로>'` | 공백 경로 |
|---|---|---|---|
| `/bin/bash`, `/usr/bin/bash` | PASS | PASS | PASS |
| `/bin/sh`, `/usr/bin/sh` | PASS | PASS | PASS |
| `/bin/dash`, `/usr/bin/dash` | PASS | PASS | PASS |
| **없는 셸** | 실패가 **기록되고** 탭 제목이 "셸 열기 실패" 가 됨 | | |

주입하는 문자열은 POSIX 셸 문법(`cd '<경로>'`)이므로, POSIX 계열에서는 전부 동작한다.

**확인하지 못한 것 (명시)**: `zsh` · `fish` 는 이 머신에 **설치되어 있지 않아**
검증하지 못했다. `LOCALES`-류로 목록을 늘리는 대신 **있는 것만** 시험했다 — 없는
셸을 시험하면 "셸이 없다" 를 검증하는 것이 되고, 그것은 호환성 문제가 아니다.

## 검사기가 스스로 거짓말을 한 횟수: 5번

이 스크립트를 만들면서 **검사가 5번 스스로를 속였습니다.** 전부 코드가 아니라
검사의 가정에서 나왔고, 전부 같은 부류였다 — **셸이 입력한 줄을 에코한다**는 걸
잊은 것.

1. `tty` 의 출력이 프롬프트에 붙어서 `tty` 가 잡혔다 → 출력을 **센티널로 감쌌다**.
2. 마커가 **에코된 명령 안**과 **실제 출력**에 두 번 나와서 `lastIndexOf` 가 앞 것을
   잡았다 → `\n` 으로 줄을 나눴다.
3. 그래도 **마커가 든 줄**이 마지막에 남아 항상 `echo __PROBE_…` 를 돌려줬다 →
   마커가 든 줄을 버렸다.
4. OSC 시퀀스가 **BEL 이 아니라 `ESC \`** 로 끝나(`]666;vte.shell.preexec!`) 이스케이프
   제거가 안 됐다 → 두 형태 다 지운다.
5. 백틱을 이스케이프하지 않고 보내니 bash 가 **명령 대입**으로 실행해
   "명령을 찾을 수 없습니다" 가 났다. 셸 버그가 아니라 **보낸 문자열**의 문제다 —
   사용자가 똑같이 치면 똑같이 난다.

**"서버가 이상하다" 는 보고의 상당수는 검사가 이상한 경우였다.** 그래서 코드를
고치기 전에 **먼저 검사를 의심**했다.

## 측정하지 않은 것 (명시)

- 사람이 느끼는 감각 — 프롬프트가 어색한지, 깜빡이는지, 타이핑 지연감이 있는지.
  60fps 이하의 렌더 품질은 이 스크립트로 알 수 없다.
- **좁은 창에서의 줄바꿈** — `fit()` 이 계산한 열 수와 실제 폭이 어긋나는지는
  브라우저가 있어야 한다.
- 동시 다중 탭의 리사이즈 경합 (탭 1개만 열었다).
